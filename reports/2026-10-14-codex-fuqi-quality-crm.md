## 定位

### 167：责任人业务录入入口缺失

Web `src/views/quality/rectification/index.vue:190-191` 使用 `el-input`，`:321` 只做必填校验，`:359-373` 直接提交表单。后端请求要求 `Long responsibleUserId`，`MesQualityRectificationServiceImpl.resolveUserName():187-193` 查 ID 回填昵称。

复现只证明用户无法按姓名选择负责人，不证明无效 ID 可以保存或跨租户越权。应复用当前租户有权限人员选择器，并回归新增、编辑、姓名回显、禁用或不存在人员和后台数据范围；不能给所有租户写固定负责人。

- [生产责任人输入框](../evidence/2026-10-13-codex-fuqi-quality-crm/rectification-owner-raw-id.png)

### 168：显示编码与关联 ID 共用字段

合同页 `loadContractReferences():2224` 用 `String(item.id)` 生成候选 `code`；`syncContractProduct():2625` 将其写入 `productCode`，UI 列名却是“产品编码”。主数据接口 `BaseMaterialVO` 分别定义 `id` 和 `code`，页面没有保留业务编码。

生产 DOM 读取标准原材料明细输入框为 `2104856930422521858`，截图中长数字被截断。产品名称、规格和金额正常回填，不能把整个选择器认定为不可用。

保存构造 `toContractSaveRequest():2299` 用 `productCode` 作为 `productId`；后端 `CrmContractSaveReqVO.Product.productId` 和持久化字段也是关联标识。修复必须分离内部 ID 与业务编码，不能只改一处候选映射造成提交关联错误。新增、历史回显、检索及打印均需覆盖，新旧租户不依赖一次性生产数据修补。
