# 2026-10-12 Codex PLM 转产与量产回流续测

## 结论

- 生产浏览器继续覆盖 `https://jixu-ai.com` 的“转产与量产回流”菜单；沿用 admin 会话，品牌为即序科技，未独立确认租户 ID。
- 新增 Bug 138/139：量产启动页固定展示演示启动单；量产放行表单没有保存或正式放行 API。
- 同轮检查的转产准备、下发包、试量产订单、生产反馈、质量反馈、回研清单列表为空，反馈中心源码走正式项目、工作台和 LIMS API；未查库确认空态原因。
- 本轮没有执行生产下发、量产放行、审批、库存/订单写入、SQL、Flyway、配置修改或服务重启。

## 生产操作

1. 打开“转产与量产回流 → 转产准备”：项目数为 0，试产/量产按钮禁用，列表显示暂无数据。
2. 打开“下发包”：项目列表为空，“执行下发”禁用，显示请选择项目生成下发包。
3. 对项目输入 `CODEX-NO-MATCH-20261012` 查询：列表为空，右侧保持正确空态。
4. 打开“试量产订单”：项目与试产状态为空，发起试产下发禁用。
5. 打开“量产导入”：出现三条启动单，其中首条为可启动。
6. 打开“生产反馈”：生产反馈列表为空。
7. 切换“质量反馈”：质量记录为空。
8. 切换“回研清单”：回研问题为空。
9. 回到“量产导入”打开“放行量产”，检查表单选项后取消，未提交。

## Bug 138 证据与根因

生产页显示：

- `ML-202605-012 / PRD-RUB-310 耐高温胶料`，状态“可启动”；
- `ML-202605-009 / PRD-SEAL-120 高耐磨密封件`，状态“门禁关闭中”；
- `ML-202605-006 / PRD-COAT-08 低气味涂层`，状态“暂缓启动”。

同一菜单的上下游列表为空，但不能由此推断数据库无项目、订单、工单或质检数据。源码直接声明固定 `launchRows`，包含生产所见的编号和产品名称，未加载当前租户正式事实源；固定演示记录才是本问题的直接依据。

## Bug 139 证据与根因

量产放行抽屉可选择：

- 放行结论：正式放行量产 / 附条件放行首批 / 暂缓量产放行；
- 首批控制：按首批全程跟踪执行 / 按关键工序加严确认 / 暂不启动首批生产；
- 反馈去向：回量产反馈页 / 回质量页 / 回工艺页。

选择后“放行摘要”随选项变化，两个动作按钮均可用；源码中两个动作按钮没有 `@click`，没有 loading、API、成功/失败消息或刷新。本轮未点击它们，主动关闭抽屉；源码功能缺口不能冒充生产点击无反应的实测。

## 修复验收要求

- 先确认 PLM、MES、生产订单/工单、质量回流和审批审计的唯一事实源及状态契约。
- 量产导入只展示当前租户有权限访问的真实启动对象；无数据显示空态，不能保留演示数组。
- 正式放行接口需要服务端权限、租户隔离、状态条件更新、幂等、事务和审计；暂存与正式放行状态必须明确。
- 重新验证新租户/存量租户初始化、菜单权限、编号规则和数据库迁移；不要通过前端本地数组或生产数据补丁绕过。
- 生产独有 AI、文件、第三方登录、公众号、企微、数字员工等配置不在本轮修改范围。
