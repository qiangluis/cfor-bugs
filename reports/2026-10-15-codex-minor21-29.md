## 根因和实现

### 我的项目系统异常

生产使用用户指定的福奇科技测试账号，两次读取
`/pms/pm/project-group/list` 均为 HTTP 200、业务码 500、“系统异常”。
主站日志 09:49:28、09:49:33 对应：

```text
PmsProjectGroupMapper.insert (batch index #1) failed
Field 'id' doesn't have a default value
PmsProjectGroupServiceImpl.ensureDefaultProjectGroupList:242
```

该表主键非自增。缺默认分组时走批量插入，实体未明确分配 ID，
运行策略依赖数据库生成主键而失败。显式 `IdType.ASSIGN_ID` 后，
新用户、缺组旧用户沿用原初始化路径，已有分组及显式历史 ID 保留。
没有修改 MyBatis 全局配置、Nacos、数据库结构或权限范围。

### 应收与收款小计

原列表从展开后的明细行计算小计。本次改取分页接口返回的原始单据集合，
按单据汇总，与既有后端全范围统计口径一致。
不去重金额相同但 ID 不同的独立单据，也不从明细重建被脱敏的主表金额。
明细展示、后端合计、审批和记账链路未改。

### 人员、部门初载闪 ID

两类弹窗先并行取得人员与部门选项，再显示表单；统一引用值为字符串，
避免 Long ID 与字符串匹配失败。选择人员仍读取其部门，无部门保留空值。
历史引用不在当前候选中时保留历史名称或“名称不可用”，不清除原 ID；
该历史选项为禁用态，公共选择器传递禁用标记。

### 助手遮挡

原收起按钮占 178×236px、层级 3000，即使透明也参与点击。
改为 48×64px、右下间距 8px、层级 1900，限制人物内容溢出，
普通业务弹窗位于助手入口上层；展开、收起及关闭入口保留。

生产审计结果中的工作台按钮坐标部分超出视口，
`elementFromPoint` 返回空值不能证明被助手挡住。
该观察只保留为原始审计，不作为生产命中断言。
本地真实助手组件及位于原遮挡区域的测试按钮点击通过，
仍需发布后滚动到生产原按钮进行验收。

### 空明细与公告输入的边界

入出库业务保存函数新增空数组兜底，提示“请至少添加一条存货明细”，
保持编辑状态且不请求业务保存。真实公共保存按钮当前已有
“请先添加数据”提示，生产对应源码 `ba2884473` 也包含该拦截。
本轮不能将这个原本已有反馈的路径称为新修复，原静默现象继续待复核。

公告编辑区第三方源码使用无效 `role=textarea`，缺少可访问名称。
公共封装补为 `role=textbox`、`aria-multiline`、`aria-readonly`，
公告指定名称“公告正文”，真实角色定位成功。
原版及修改后直接键盘输入 `ABCdef XYZ 123`、Shift+A 均完整保留，
没有复现大写丢失；不改写第三方键盘事件，也不声称丢字符根因已解决。
