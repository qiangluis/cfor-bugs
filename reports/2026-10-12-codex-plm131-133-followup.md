## 新发现的边界

### 131：服务端基线比较没有差异计算

实际调用链为 Web 正式 compare API → `PlmCoreBaselineController` → `PlmCoreBaselineServiceImpl.compareBaseline()`。
该方法读取左右对象后固定设置空 items 与全部零统计，没有比较快照。设计文档《PLM全域业务流与页面设计》明确基线对比应比较两基线对象差异。

生产仅有一条当前可见产品基线，没有创建第二条；此前同基线无差异的回归不能验证不同基线算法。后续需先核对快照结构、版本兼容与正式差异口径。

### 132：空关卡显示 25%

生产列表为零条，摘要同时显示“未选择”“未绑定”和 `25%`。
Web 已改为空对象显示 `-`，不改变既有阶段及状态算法。

### 133：实验项目名称不建立 ID 关系

直接从菜单新建时没有 `queryParams.projectId`；表单仅让用户输入项目名称。
后端只保存 ID，不按名称查询项目；关联导航必须依赖 ID。当前可以确认的是 UI 缺少建立项目关系的路径，不是已经在生产保存后造成孤立数据。
DOE 的同类新增表单已有项目选择控件，可作为既有实现参考。独立实验是否允许、服务端项目是否必填仍需确认，不能只为本条测试强制修改业务边界。
