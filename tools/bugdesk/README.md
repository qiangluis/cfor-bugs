# CFOR Bug 工作台

在本机或同一局域网的电脑写 Bug 描述、粘贴或拖入截图、预览 Markdown，再点击“提交并推送”。
报告会写入仓库根目录，截图写入 evidence/，问题同时登记到 BUG-LIST.md，状态为“待修复”。

## 启动

双击 start.cmd，保持启动窗口开启，启动窗口会显示本机局域网地址，例如 http://192.168.110.22:3212/ 。本机和同一网络的其他电脑都使用这个地址。
工具默认连接所在仓库；首次使用可先点击“拉取最新内容”。

工具在本机局域网 IPv4 地址上提供共享入口，沿用正在运行的工作台和 GitHub 授权；重复启动不会替换已有的后台服务。草稿和截图自动保存在各自浏览器，提交后的报告统一写入主机仓库，所有人共用主机已授权的 GitHub 账号。同一时间只执行一次同步；遇到“正在同步”提示，稍后重试即可。

若其他电脑连接被 Windows 防火墙拦截，在管理员 PowerShell 执行 `./allow-lan.ps1 -Address 192.168.110.22 -Port 3212`。防火墙规则仅放行本机这个地址、Node.js 的 TCP 3212 端口和本地子网，保持其他防火墙规则不变。请使用启动窗口实际显示的 IP；网络分配的 IP 变化后需重新启动，并按需针对新地址添加规则。

指定其他仓库：

    .\start.ps1 -Repo "C:\你的路径\cfor-bugs" -Port 3212

指定本机网卡地址：

    .\start.ps1 -Address 192.168.110.22 -Port 3212

需要 Git 和 Node.js 22 以上版本。此电脑会优先使用已经安装的 Node.js 和 Git。

## 使用

1. 填写标题和问题描述，也可以填写复现步骤、实际结果和预期结果。
2. 直接 Ctrl+V 粘贴截图，或选择、拖入图片。点截图右上角 × 可移除。
3. 点击“预览 Markdown”核对，再点击“提交并推送”。
4. 推送失败时，报告、截图和本地提交会保留。处理登录或网络问题后点击“重试待推送报告”，不会重复登记。
5. 如果远端有更新，先点击“拉取最新内容”，再重试推送。存在合并冲突时需处理后继续。

页面草稿（包括截图）自动保存在当前浏览器。成功推送后，当前报告的草稿会清空。
“仓库文档”可查看顶层 Markdown 清单、修复日志和历史增量报告。

工具可以使用本机已有的 Git 凭据。若页面提示尚未连接，请点击“连接 GitHub”，在 GitHub 设备授权页面输入验证码并确认授权，再点“验证推送权限”。

浏览器登录 GitHub 后仍需要授权本地工具。工具通过 Git Credential Manager 的官方设备登录流程获取授权，并检查当前账号对 qiangluis/cfor-bugs 的写入权限。若账号收到了这个仓库的协作者邀请，页面会显示“接受仓库邀请”；点击接受后即可验证推送。工具只处理 qiangluis/cfor-bugs 的邀请，不会接受其他仓库的邀请。

令牌只保存在运行中的工具内存中，重启后需要重新授权；不会写入报告或仓库文件。授权后如果网络中断，工具会自动重试检查，不需要再次授权。

提交署名为 CFOR BugDesk <bugdesk@localhost>，不会修改全局 Git 配置。
