# CFOR Bug 工作台

在本机写 Bug 描述、粘贴或拖入截图、预览 Markdown，再点击“提交并推送”。
报告会写入仓库根目录，截图写入 evidence/，问题同时登记到 BUG-LIST.md，状态为“待修复”。

## 启动

双击 start.cmd，保持启动窗口开启，在浏览器访问 http://127.0.0.1:3212 。
工具默认连接所在仓库；首次使用可先点击“拉取最新内容”。

指定其他仓库：

    .\start.ps1 -Repo "C:\你的路径\cfor-bugs" -Port 3212

需要 Git 和 Node.js 22 以上版本。此电脑会优先使用已经安装的 Node.js 和 Git。

## 使用

1. 填写标题和问题描述，也可以填写复现步骤、实际结果和预期结果。
2. 直接 Ctrl+V 粘贴截图，或选择、拖入图片。点截图右上角 × 可移除。
3. 点击“预览 Markdown”核对，再点击“提交并推送”。
4. 推送失败时，报告、截图和本地提交会保留。处理登录或网络问题后点击“重试待推送报告”，不会重复登记。
5. 如果远端有更新，先点击“拉取最新内容”，再重试推送。存在合并冲突时需处理后继续。

页面草稿（包括截图）自动保存在当前浏览器。成功推送后，当前报告的草稿会清空。
“仓库文档”可查看顶层 Markdown 清单、修复日志和历史增量报告。

工具可以使用本机已有的 Git 凭据。若页面提示尚未连接，请点击“连接 GitHub”，在 GitHub 设备授权页面输入验证码并确认授权，再点“验证推送权限”。

浏览器登录 GitHub 后仍需要授权本地工具。工具通过 Git Credential Manager 的官方设备登录流程获取授权，并检查当前账号对 qiangluis/cfor-bugs 的写入权限。令牌只保存在运行中的工具内存中，重启后需要重新授权；不会写入报告或仓库文件。

提交署名为 CFOR BugDesk <bugdesk@localhost>，不会修改全局 Git 配置。
